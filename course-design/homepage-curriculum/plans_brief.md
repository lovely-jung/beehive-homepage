# 차시별 수업안 작성 기준 (홈페이지 course.html '차시별 수업안')

사용자 요구: 홈페이지 각 수업 페이지에 "실제 차시별 상세 수업안"을 넣는다. 매 차시 수업 설계와 기획력이 좋아야 한다.
기준 예시(골드 스탠다드): /Users/jung/Downloads/비하이브 홈페이지/assets/data/plans.js 의 'ai-how'.elem — 이 수준·형식을 그대로 맞춘다.

## 형식 (JS 조각, 작은따옴표, 2칸 들여쓰기, plans.js 예시와 동일)
  '<수업 id>': {
    <대상키>: [
      { title, min, hook, aim, flow: [['단계', 분, '활동'], ...], ask, extra, out },
      ...
    ],
  },
- 대상키·수업 id는 assets/data/courses.js 의 그 수업 levels 키와 똑같이. 모든 대상 레벨을 빠짐없이 작성.
- 차시 수 = 그 레벨 steps 줄 수. title = 해당 steps 줄에서 ' — ' 앞부분과 글자까지 똑같이.
- 각 차시 내용은 steps 줄의 ' — ' 뒤 설명, 그 레벨 goal·tools·output과 맞물려야 한다. 설계 의도는 <분야>_02_design.md 참고.
- min: 차시 시간(분). '2차시 × 40분'이면 40. 캠프·연수처럼 블록(1부, 오전 1, 모듈)이면 블록 분량을 합리적으로 정하고(예: 6시간 4블록 → 각 80~100분, 합계가 time과 맞게), 학기 과정의 '3~6차시' 같은 묶음 줄은 묶음 전체 분(4×45=180)으로 쓰고 flow 단계 이름에 차시를 표기(예: '3차시', '4차시').
- flow 분 합계 = min 정확히. 40~50분 차시는 한 칸 최대 10분. 90분 이상 블록은 한 칸 최대 20분.
- 단계 이름은 '도입 · 활동 1 · 개념 · 시연 · 공유 · 정리' 등 실제 성격대로. 모든 차시를 같은 틀로 찍어내지 말 것.

## 품질 기준 (lesson-planner + creative-lesson-architect)
- hook: 이 차시를 여는 장치 + 왜 뻔하지 않은지를 한 문장으로.
- aim: 관찰 가능한 행동("~한다"). "이해한다/중요성을 안다/다양한 ~를 탐색한다" 금지.
- flow 각 칸: 누가 무엇을 몇 개·어떤 재료로 하는지 구체적으로(카드 몇 장, 몇 번 시험, 어떤 조건). "자유 토의", "질의응답", "발표"처럼 내용 없는 칸 금지.
- 학생 활동 비율: 초 70%+, 중 65%+, 고 50%+, 교원 40%+. 강사 설명(개념·시연) 연속 최대: 초 7분, 중 10분, 고 15분, 교원 20분.
- 활동 형식을 차시마다 바꾼다(몸 활동, 실험, 제작, 역할, 측정, 사용자 테스트 등). 모둠 토의→대표 발표 반복 금지. 포스트잇 브레인스토밍·마인드맵·포스터·골든벨·카훗을 핵심 활동으로 쓰지 않는다.
- ask: 그 차시의 핵심 개념을 생각하게 만드는 진짜 질문 1개 (예/아니오로 끝나지 않게).
- extra: 시간이 남을 때 바로 할 심화 미션 1개, 구체적으로.
- out: 그 차시에 실제로 남는 산출물.
- 연령·툴: 13세 미만은 생성형 AI 직접 사용 금지(교사 시연). 무료 도구. 안전이 필요한 활동은 flow 안에 안전 확인 한 줄.
- 문체: 이모지 금지, "~해볼까요/정말 좋아요" 금지, 같은 문장 틀 반복 금지. 홈페이지 공개용이니 학교 담당자가 읽어 이해되는 말.
- 다른 분야 수업과 같은 훅을 반복하지 말 것('재판', '블라인드', '해킹', '깨기'는 이미 정리된 수업 외에는 쓰지 않는다).

## 산출

- 작성 후 node로 검증: 조각을 `window.BH_PLANS={` + 내용 + `}`로 감싸 eval, courses.js를 로드해 모든 id·레벨 존재, 차시 수 = steps 수, title = steps의 ' — ' 앞부분, flow 분 합계 = min, 칸 최대 분 규칙을 자동 확인하고 통과할 때까지 고친다.
- courses.js, plans.js 는 수정하지 말 것.
